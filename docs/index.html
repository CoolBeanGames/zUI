zUI

zUI is a themeable UI subsystem that sits on top of native host applications (a music app, a game engine, a project-management app) so they all present one consistent interface. It is CSS + a small JS runtime rendered inside a web view the host owns, driven by an ahead-of-time UI language.

Pieces

PathWhat
core/css/token system, one stylesheet per component, themes
core/js/zui.jsruntime: component behaviours + host↔UI message bus
core/icons/monochrome line-icon sprite
compiler/zslc.pythe ZSL / ZML compiler (html / csharp / cpp backends)
bindings/csharp, bindings/cpphost bindings (WebView2)
showcase/gallery + a realistic music-browser mock
samples/runnable C# and C++ host apps

Design identity

Default theme holo — Google's Android Holo look (dark, Holo-blue #33b5e5). Light alternative clean. See Theming and design.txt.

Getting started

1. Vendor it

git submodule add https://github.com/CoolBeanGames/zUI.git third_party/zui

2. A zUI document

A zUI screen is a normal HTML file that links the core:

<html data-zui-theme="holo">
<link rel="stylesheet" href="zui/css/zui.css">
<link rel="stylesheet" href="zui/css/themes/holo.css">
<script src="zui/icons/sprite.js"></script>
<script src="zui/js/zui.js"></script>

Author it by hand, or compile it from ZSL / ZML (next section). Then load it in the host through a binding.

Embedding

Both bindings embed the identical core/ assets, so the result is pixel-identical. Runnable examples: samples/csharp/, samples/cpp/.

C# (WinForms / WPF + WebView2)

var ui = new ZUI.ZuiHost(webView2Control);
await ui.InitializeAsync();
await ui.LoadAsync("ui/main.html");
ui.On("save", json => Save(json));
ui.Send("theme", "holo");

C++ (Win32 + WebView2)

zui::Host ui(hwnd);
ui.set_core_root("zui");
ui.load("ui/main.html");
ui.on("save", [](const std::string& j){ save(j); });
ui.send("theme", "\"holo\"");

The C++ WebView2 backend is bindings/cpp/zui_webview2.cpp; it needs the WebView2 SDK + WIL at build time and the evergreen WebView2 runtime to run.

ZSL / ZML language

UI is written in ZSL (brace) or ZML (angle-bracket) and compiled ahead of time — never interpreted at runtime. zslc.py auto-detects: a source starting with < is ZML. Both build the same tree and produce byte-identical output.

panel "Tracks" { button "Play" }
<panel title="Tracks"><button>Play</button></panel>

Compile

py compiler/zslc.py ui/main.zml --backend html   -o ui/main.html
py compiler/zslc.py ui/main.zml --backend csharp -o Ui.g.cs
py compiler/zslc.py ui/main.zml --backend cpp    -o ui.g.cpp

Bindings & events

  • bind:x — two-way binding to a state field; also marks the node data-zui-id="x".
  • export="name" — mark any node for the runtime IO layer.
  • -> some.event / on="some.event" — runs the matching on { } handler, else emits it.
  • source=items — repeats a table/container per element of state.items.

Full grammar and node list: compiler/GRAMMAR.md.

Layout & components

Layout is flow/flex — never x/y. Nest row / col, mark the stretchy one fill, use sidebar, splitter, grid, the gap-* / pad-* scale (4/8/12/16/24), and panel for a bordered region.

Component set

window shell & menu bar · nav / tab strips (closeable) · tree · panels & splitters · buttons (default / primary / icon / toggle / split / busy) · text / search / number inputs & validation · checkbox / radio / switch · sliders (single + dual) · dropdown & context menus (submenus, mnemonics) · tables (sortable, resizable, virtualised) & lists · dialog & popover · toasts & badges & status glyphs · spinner / progress / skeleton · drop targets · status / device bar · playback / contextual bar.

Live examples: open showcase/index.html and showcase/music.html.

Message bus & component IO

One JSON channel carries everything: { channel, payload }.

zui.send(channel, payload)          // UI  -> host
zui.receive(channel, handler)      // host -> UI

Component IO

Any element with data-zui-id (ZSL/ZML export=) is readable and writable both ways — text, checkbox, radio, select, progress, button clicks/state, sliders, scroll positions.

zui.values(scope?)   // { id: value, ... }
zui.field(id)        // one value
zui.set(id, value)   // write (zui.set({id: value, ...}) for many)
zui.bind(id, fn)     // fn(value) on every change
DirectionChannels
UI → hostvalue {id,kind,value} · submit {form,values}
host → UIset · set-many · query

Component channels: tab, selection, select, toggle, drop, reorder, tree, splitter, window, transport, device-action, theme-changed. Host can push theme, toast, dialog, device, now-playing, state. Full contract: core/PROTOCOL.md.

Interaction & keyboard

All shared behaviour is centralised in core/js/zui.js — reuse it, never reimplement.

zui.shortcuts({ "Ctrl+K": fn })            // global shortcuts
zui.history.push({ label, undo(), redo() }) // Ctrl+Z / Ctrl+Y wired by default
zui.cursor.while(name, promise)             // scoped cursor state
zui.renameInPlace(el, onCommit)             // Enter/blur commit, Esc cancel
zui.dialog({title, body, buttons})          // -> Promise; zui.confirm(msg)
zui.popover(anchor, content)

Declarative: data-zui-shortcut="Ctrl+K", data-zui-dblclick="channel", data-zui-context='[…]', data-zui-tip="…", data-zui-rename="channel".

Menus, tabs, tree and tables are fully keyboard-operable (arrows, Home/End, type-ahead, mnemonics). Selection helpers support ctrl / shift multi-select.

Theming & tokens

Every component is styled only through the custom properties in core/css/tokens.css. A theme is one file that re-declares them under [data-zui-theme="name"] — no component CSS changes.

ThemeLook
holo (default)Android Holo — dark, Holo-blue accent, accent caps headers
cleanlight neutral native-Windows-utility palette
zui.setTheme("clean");        // in the page
host.Send("theme", "clean");  // from the host

To add a theme: copy themes/clean.css, rename the selector, set every token (list in core/css/THEMES.md), add the <link>. tests/check-tokens.py enforces that no component hard-codes a colour and that themes stay in sync.

Typography tokens: core/css/TYPOGRAPHY.md.

Icons

One consistent monochrome line set (16×16, 1.5 stroke, currentColor) in core/icons/zui-icons.svg. No emoji as UI icons.

<script src="zui/icons/sprite.js"></script>   <!-- inject once -->
<svg class="zui-icon"><use href="#play"/></svg>

.zui-icon is 14px and follows text colour; --sm / --lg / --muted. Names and how to add one: core/icons/README.md.

Building & tests

./build.ps1 -Config debug     # -> builds/debug
./build.ps1 -Config test      # + runs every test suite
./build.ps1 -Config release   # -> builds/release

It stages core/, compiles the ZSL/ZML examples, and builds whichever bindings have a toolchain (missing ones are skipped with a warning).

Test config runs

  • compiler/tests/test_compile.py — lexer, both parsers, all backends
  • tests/io-selftest.html — the runtime component-IO layer (headless)
  • tests/check-tokens.py — no hard-coded colours, themes in sync
  • bindings/cpp envelope unit test (when CMake is present)
